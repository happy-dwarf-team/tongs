Tongs selectors: prototype

Throwaway prototype for the planning ticket "What do selectors and the ui tree answer look like?" (happy-dwarf-team/tongs#21).

Question. Does this selector grammar let an agent name the widget it means, and do the answers of ui find, ui tree and ui click tell it enough to act or to know why it can't? Look especially at repeated names, event options, hidden widgets, a covered button and a disabled option.

The screen. The widget names and nesting come from the game's own speed_controls.gui and eventwindow.gui. The pixel rectangles are invented, except the three speed buttons, which use the points that worked in the live check (3350,32 / 3350,62 / 3407,27). ProtoOverlay is a made-up window that covers the speed buttons.

Grammar. a/b means b is a child of a, and a//b means b is anywhere inside a. A selector that starts with a name is anchored at the top-level windows; one that starts with // searches everywhere. Names ignore case and allow * and ?. Filters in brackets: [2] (the 2nd match, counting from 1), [type=button], [text="…"], [text~="…"] (contains), [text^="…"] (starts with), [enabled], [disabled]. Hidden widgets, and everything inside a hidden window, are left out unless the command ends with all.
